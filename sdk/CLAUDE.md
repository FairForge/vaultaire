# sdk/

The Private-mode key core (keystone K2, plan Phase 10.0.1, decision F-12): the one implementation of the client-side cryptography, in Go, compiled unchanged for the browser. Nothing here runs on the server for customer data — Private mode means these keys exist only on the device. The server's Standard mode (`internal/crypto`) is a different thing: AES-256-GCM + ML-KEM-768 with keys we hold.

- **`go/e2ee/`** — the constructions (owner decision 2026-10-22: ChaCha + post-quantum on the client), every output led by an authenticated format byte:
  - `0x01` **box** `Seal`/`Open`: XChaCha20-Poly1305 (`golang.org/x/crypto/chacha20poly1305` `NewX`), random 192-bit nonce; AD = the caller's purpose (a sealed key cannot move to another role). Keys, metadata, manifests.
  - `0x02` **convergent chunk** `ChunkKey`/`SealChunk`/`OpenChunk`: key = HKDF-SHA256(space key, info = label ‖ SHA-256(chunk)); nonce = HMAC-SHA256(chunk key, label ‖ plaintext)[:24] (the R8-01 lesson: one key may meet two messages — raw and compressed). A space dedups its own chunks; two spaces never converge (F-12 change 1). With `RandomKey` = the paranoid flag. ≤ `MaxChunk` (16 MiB, the frozen chunker's max). **The v1 bytes are pinned** (`goldenChunk`, key and nonce recomputed independently from RFC 5869): a change is a new format byte and a knowing dedup reset.
  - `0x03` **sealed box** `GenerateKeyPair`/`PublicKey`/`SealTo`/`OpenSealed`: HPKE base mode (Go 1.26 `crypto/hpke`) with MLKEM768-X25519 = X-Wing (draft-ietf-hpke-pq, KEM 0x647a), HKDF-SHA256, ChaCha20-Poly1305 — post-quantum hybrid key sharing (F-12 change 2); the suite of age's `age1pq` recipients. Private key = X-Wing's 32-byte seed, public key 1216 bytes, encapsulation 1120. `info` is prefixed with the package label.
  - Tests: KATs `TestBox_XChaCha20Poly1305_KnownAnswer` (draft-irtf-cfrg-xchacha A.3.1 via x/crypto's vectors) and `TestSealedBox_HPKE_XWing_KnownAnswer` (Go's own hpke-pq vector, `testdata/hpke_xwing_vector.json`); `TestChunk_ConvergentWithinASpace_NeverAcross`, `TestChunk_DeterministicNonceSeparatesMessages`, `TestBox_SealOpen`, `TestSealedBox_RoundTripAndBinding`; **`TestE2EE_WASMMatchesNative`** builds `sdk/wasm`, loads it through `js/e2ee/index.mjs` in node (`testdata/cross.mjs`) and proves both directions plus byte-identical chunk ciphertext (skipped without node or in `-short`).
  - Not yet (the rest of K2): Argon2id KEK + recovery key, the hierarchy's wraps and labels, manifests, the chunker in WASM pinned to the golden boundaries, SRP. It lives in the main module for now (CI covers it); its own `go.mod` when a third party imports it.
- **`wasm/`** — `main.go` (`//go:build js && wasm`): registers `globalThis.storedE2EE`; every function takes/returns `Uint8Array` and answers `{value}` / `{error}`. `make sdk-wasm` → `wasm/dist/{e2ee.wasm,wasm_exec.js}` (gitignored; the `wasm_exec.js` of the SAME toolchain). Lint it with `GOOS=js GOARCH=wasm golangci-lint run ./sdk/wasm/` (the default lint skips the build tag). 3.8 MB, 1.1 MB gzipped.
- **`js/e2ee/index.mjs`** — `load(wasmBytes)`: the thin binding (throws the Go error message); no cryptography in JavaScript.
