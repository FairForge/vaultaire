# sdk/

The Private-mode key core (keystone K2, plan Phase 10.0.1, decision F-12): the one implementation of the client-side cryptography, in Go, compiled unchanged for the browser. Nothing here runs on the server for customer data — Private mode means these keys exist only on the device. The server's Standard mode (`internal/crypto`) is a different thing: AES-256-GCM + ML-KEM-768 with keys we hold.

- **`go/e2ee/`** — the constructions (owner decision 2026-10-22: ChaCha + post-quantum on the client), every output led by an authenticated format byte:
  - `0x01` **box** `Seal`/`Open`: XChaCha20-Poly1305 (`golang.org/x/crypto/chacha20poly1305` `NewX`), random 192-bit nonce; AD = the caller's purpose (a sealed key cannot move to another role). Keys, metadata, manifests.
  - `0x02` **convergent chunk** `ChunkKey`/`SealChunk`/`OpenChunk(key, msg, expectedHash)`: key = HKDF-SHA256(space key, info = label ‖ SHA-256(chunk)); nonce = HMAC-SHA256(chunk key, label ‖ plaintext)[:24] (the R8-01 lesson: one key may meet two messages — raw and compressed). `OpenChunk` checks SHA-256(plaintext) against the manifest's hash (`ErrChunkMismatch`: a member cannot poison dedup). The server only ever sees **`ChunkID`** = HMAC-SHA256(HKDF(space key, `chunk-id`), SHA-256(chunk)) — keyed, never the plain hash (WASM's `deviceOnlyChunkHash` never leaves the device). A space dedups its own chunks; across spaces the bytes and ids never converge, **the lengths do** (len + 41 — F-35). With `RandomKey` = the paranoid flag. ≤ `MaxChunk` (16 MiB). **The v1 bytes are pinned** (`goldenChunk`): a change is a new format byte and a knowing dedup reset.
  - `0x03` **sealed box** `GenerateKeyPair`/`PublicKey`/`SealTo`/`OpenSealed`: HPKE base mode (Go 1.26 `crypto/hpke`) with MLKEM768-X25519 = X-Wing (KEM 0x647a), HKDF-SHA256, ChaCha20-Poly1305. HPKE info = `stored.cloud/e2ee/v1/sealed/` ‖ **0x03** ‖ the caller's info (RP37-12, pinned by `TestSealedBox_GoldenOpens`). Private key = X-Wing's 32-byte seed, public key 1216 bytes, encapsulation 1120.
  - **The hierarchy (K2b, 2026-10-22; `docs/reviews/WP-P31.md`, `docs/ENCRYPTION.md` § Client-side keys):**
    - `account.go`: **`0x04` password wrap** = header (Argon2id m KiB, t, p, salt) ‖ box under the KEK, header in the AD; `Sensitive` 256 MiB/t3/p1 (default), `Interactive` 64 MiB/t3/p1 = **the floor** — a wrap under it (or over 1 GiB / t16 / p16) is refused before anything is derived. Recovery key = 32 random bytes as **24 BIP-39 words** (`mnemonic.go`, the MIT wordlist vendored with its sha256 pinned; encoding only, never BIP-39's seed). Boxes: master ← recovery key, recovery key ← master key, recovery key ← **vault key** (the 32-byte secret the K5 realms protect; D-P31-1).
    - `identity.go`: X-Wing + Ed25519 (`alg ‖ key`, signature `alg ‖ sig` over lp(context) ‖ msg; **`0x02` held for Ed25519 + ML-DSA-65, F-34**, refused today); both private keys boxed under the master key; `Fingerprint` = SHA-256 over both public keys, text = base32 of 160 bits.
    - `share.go`: space key boxed under the master key (AD names the space id); **`0x05` share** = SealTo the member + the sender's signature; `OpenShare` refuses another recipient, an unsigned share, a sender other than the trusted one.
    - `manifest.go`: object key boxed under the space key (AD names space + object); **manifest v1** boxed under the object key (AD names space, object, version) binds the ordered chunks (id, hash, key, sizes), the total, the compressor, the previous manifest's hash; `OpenManifest(…, seen)` refuses an older version, a fork and a broken chain; `OpenChunkAt` refuses a chunk out of order, from another object or poisoned.
    - Every variable field of a fixed encoding is `lp` (be16 length ‖ bytes). Labels share the prefix `stored.cloud/e2ee/v1/`.
  - Tests: every construction has a golden in **`testdata/vectors.json`** (written once by `vectors_gen_test.go`, `-tags e2eegen`, which never rewrites a section; the deterministic ones recomputed by `testdata/vectors_check.py` with libsodium + OpenSSL + the stdlib — run by hand); KATs for XChaCha20-Poly1305, HPKE X-Wing, Argon2id, BIP-39; one refusal test per attack; **`TestE2EE_WASMMatchesNative`** builds `sdk/wasm`, loads it through `js/e2ee/index.mjs` in node (`testdata/cross.mjs`), checks every golden of `vectors.json` in WASM and every construction both ways (skipped without node or in `-short`). The chunker in WASM is DONE (WP-EDGE-2: `chunkerwasm/` below, pinned to the golden boundaries). The Argon2 tests run in parallel (`-race` ~16 s). `testdata/leakage` = the F-35 measurement (out of `./...`).
  - Not yet (the rest of K2): SRP/OPAQUE (10.0.5), the browser upload path, the paranoid flag's wiring, key transparency (K4b). No "zero-knowledge" and no "keys are wiped" claim: WASM never zeroes a key. It lives in the main module for now (CI covers it); its own `go.mod` when a third party imports it.
- **`chunkerwasm/`** — the FROZEN chunker (internal/crypto, WP-R8-4) compiled to WebAssembly for the edge codec's data-plane host (WP-EDGE-2; client `edge-chunker`, built by `scripts/build-client.sh` into `edge/s3-ingest/src/wasm/chunker.wasm`, gitignored; `make edge-wasm` — which also builds `e2ee.wasm` (client `sdk-wasm`, by the RECIPE: `make sdk-wasm` gives other bytes) and `wasm_exec.js` (client `edge-wasm-exec`) for the Worker 0.3.0, WP-EDGE-2 Part B; linted by `make lint-wasm`). `globalThis.storedChunker`: `create()` → id, `push(id, Uint8Array)` → completed chunk lengths, `finish(id)`, `free(id)`, `goldenBody(seed, n)` (the golden tests' body, generated inside the module). Boundaries reset per instance — each multipart part is chunked alone. Pinned byte-identical to Go on the 100 MiB golden body (`internal/crypto/testdata/chunker_golden.json`; `edge/s3-ingest/test/chunker.test.js` under `make test-edge`); ~123 MB/s in node.
- **`wasm/`** — `main.go` (`//go:build js && wasm`): registers `globalThis.storedE2EE`; every function takes/returns `Uint8Array` and answers `{value}` / `{error}`. `make sdk-wasm` → `wasm/dist/{e2ee.wasm,wasm_exec.js}` (gitignored; the `wasm_exec.js` of the SAME toolchain). Exports every construction of the hierarchy (identities, manifests and chunk refs as plain objects; versions as numbers). Lint it with `make lint-wasm` (RP51-2, #943: the pinned linter built for the host into a temporary GOBIN, then `GOOS=js GOARCH=wasm … run ./sdk/wasm/` with the full `.golangci.yml`; CI runs it after Lint), because `make lint` skips the build tag and `go run` under `GOOS=js` would build the linter for js. 4.4 MB, 1.2 MB gzipped (2026-10-22).
- **`js/e2ee/index.mjs`** — `load(wasmBytes)`: the thin binding — a list of the exported names, each throwing the Go error message; it fails at load if the module lacks one. No cryptography in JavaScript.
