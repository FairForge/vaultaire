## Cleared (the attacks that did not hold)

- **PKCE / codes:** `S256` required (plain or absent → `invalid_request`), the verifier compared with `subtle.ConstantTimeCompare`, the code claimed by one `UPDATE … RETURNING` BEFORE the client / redirect / verifier check (a wrong verifier burns it — D-STRIPE-74 holds), 10 min, bound to `client_id` + `redirect_uri`.
- **Registration:** https needs a host; http only `localhost` / loopback (`localhost.evil.example` refused live); fragments and javascript/data/file/vbscript/blob/about refused; `/oauth/authorize` answers every error itself (400, no `Location`) — the f18f3839 open-redirect fix holds; `client_name` is html/template-escaped.
- **Consent:** `state` round-tripped on approve and deny; the POST is behind `csrf` + `act()` (role `ActionManagementKey`) + a fresh TOTP; no 2FA = no consent; the return-to cookie is a PATH allow-list (`/dashboard/agents/connect`, `/dashboard/claim/<token>`), 15 min, HttpOnly/Secure/Lax; `IssueAgentCode` re-validates the request server-side; the page names the client and its return host.
- **Token:** `Cache-Control: no-store` + `Pragma` (live), Bearer, `expires_in`; the key is shown once; the sandbox key dies with the grant; `token_endpoint_auth_methods_supported: none` (public clients, PKCE the proof — RFC 9700-consistent). A SigV4 header on `POST /oauth/token` → 403 XML (the gate holds); Bearer passes.
- **Never Private:** the guard runs on the common path after BOTH header and presigned verification (`s3.go:556`), covers the copy source; `ListBuckets` filters `mode <> private`; an STS token inherits its parent's `agent_grant_id` (`handlers.go:244-271`) — no STS bypass; a Standard → Private flip is seen on the next request; the management API has no public mode, so D-STRIPE-75's "unreachable" holds; every person-only route carries `requirePerson` (except RP90-16's list).
- **Part 0 (the size-aware cap):** every S3 200/206 sets `Content-Length` from the row (ranges too), `/cdn` at `cdn.go:181`; 304/412/416 and HEAD are never charged; the credit-back runs in `finish()` after a client abort (`planned − sent`); the pre-charge is one transaction of conditional UPDATEs rolled back on the first miss; the holder lock order = key then bucket (as `holders.go`); the edge admit pre-checks `length > left` and counts at commit (RB13-1 as stated).
- **Approvals:** IDOR closed (tenant-scoped `GetApproval`, `isUUID`); approve needs a person with the act's own role; the TOTP is the login's `ConsumeTOTPCode` store; the spend is one conditional UPDATE under `FOR UPDATE SKIP LOCKED`; sandbox asks are `sandbox/`-prefixed on the account (D-STRIPE-76). S3 `DeleteBucket`, `PutBucketVersioning` and ACLs are outside the ceiling.
- **Apps:** "paying" = `tenant_quotas.tier != 'free'` (a lapsed house keeps the tier until `entitlement_lapse` clears it — latent); the 25 count excludes scheduled apps and a schedule has no cancel path; depth 3 refused; the app key's platform calls are pinned to its own app (`platform_tenants.go:174-184`); `ErrUnverifiedNeverPublic` is in the one door, create refuses `mode: public` by the DeveloperModes list.
- **Claimables:** the purge-vs-claim race is closed (`FOR UPDATE OF c, t` + `provisional_until` NULLed in the claim's transaction); the purge revokes both key kinds; `MovePoolTx` locks roots in id order; the request log stores no path (the token reaches HAProxy's log only); 1 GiB via `tenant_quotas`; the provisional's `pool_root_id` is the partner's.
- **Export / erasure / 122:** the agents section is ids, names, caps, timestamps (no hash); the codes table is excluded whole; codes erased by user and by tenant, grants and approvals and claims by tenant, `granted_by` / `decided_by` / `created_by` nulled, `claims.partner_tenant_id` blanked; cascades from `tenants` and `management_keys`; no existing column changed meaning (the RP84 check).
- **Worker + #1106:** the bearer is forwarded only to `STORED_API` over https and never logged; a one-call key expires in 15 min even when its revoke fails; `objectPath` RFC 3986-encodes; the live PRM names `https://stored.cloud`; `/mcp` 401 carries the right `www-authenticate`.
