**Verdict: HOLDS at P1 — one P1 LIVE for every tenant, fixed by this review (#1142); one P2 live in shape for the two `edge_ingest` tenants, closed at the control plane by the same PR and handed to Prompt 58 Part 0 for the Worker.** D-POST-2 computed the file's size as "the body less the fields before the file and the closing delimiter", which is right only when the file is the form's LAST part. A form with any part after the file input — a named submit button, a hidden field below it, the ordinary HTML of an upload page — put that part's bytes INSIDE the stored object: the body did end at the real closing delimiter, so the tail check passed, the PUT path measured exactly the declared length, and the object was stored corrupted (file ‖ `\r\n--boundary\r\nContent-Disposition…` ‖ the field) with a 204/201 and an ETag of the wrong bytes. S3 ignores parts after the file; the closeout's Step 0 said "so does Stored (never read)" — Stored stored them. Live at the origin since `05a51597` deployed (2026-11-03 ~22:00 UTC; the two `request_log` PostObject rows on prod are the session's own proofs, both with the file last). At the edge the same size is computed, and the Worker 0.7.0 cannot refuse even a WRONG closing delimiter: `FixedLengthStream` ends the backend body at its byte count, so the tail check that runs after the last file bytes were enqueued is swallowed and the commit lands (proven in workerd).

## Cleared (the attacks that did not hold)

- **The one verifier, the fourth entrance:** `LookupCredential` resolves the key (revoked → 403 `InvalidAccessKeyId`, STS parent honoured), `deriveSigningKey` is the verifier's own, the compare is constant-time and runs BEFORE any condition is checked, the IP allow-list is held to `clientip.FromRequest`; no entrance of `internal/auth` reads `X-Amz-Security-Token` (the header path does not verify it either, so the POST entrance is not weaker); the credential's date and region are the signer's, nothing pins them — as the presigned path, D-POST-3 as written.
- **Per-key and per-bucket caps hold on POST at both doors:** `WithKeyScope` is applied to the INNER request (`s3.go:489`) and to the edge's `sctx` (`edge_ingest.go:529`). Probes: `written_by_key` = the scoped key; the second form past a 100-byte key cap → 403 `QuotaExceeded`, `x-stored-cap: key` (origin) and `X-Stored-Cap: key` (edge, `attrs.acting_key` set); a bucket cap the same.
- **`${filename}`:** Go's `mime.ParseMediaType` decodes RFC 2231 `filename*=UTF-8''up%2F..%2Fesc.txt` to `up/../esc.txt` → refused; `"   "` is a legal key tail; a filename containing `${filename}` stays literal (single-pass `ReplaceAll`); 2,000 bytes → `KeyTooLongError` at the inner request; `a%2Fb` stored literally (as AWS). The unexpanded-key evaluation cannot escape a `starts-with` prefix because `/`, `\`, `..` are refused in the filename (MinIO substitutes first; no exploitable difference).
- **`starts-with ""` on `$bucket` / `$key`** is the signer's own choice, identical on AWS.
- **The gate:** the one-segment POST web routes are `/login`, `/register`, `/forgot-password`, `/reset-password`, `/abuse`; nothing posts multipart (no `enctype=multipart`, no `FormData` in the templates or the landing). A `curl -F` to them gets S3 XML; a browser loses nothing.
- **Bounds:** the preamble `ReadSlice` fails at 64 KiB, `byteCounter.limit` 84 KiB until the file part, `consumed() > 20 KiB` per byte; `check` is O(conditions × fields) over ≤ 20 KiB. `Location` follows the Host header (XML-escaped, path-escaped) — behind Cloudflare/HAProxy the Host is the zone's.
- **The inner request runs every post-auth check** (reserved tenant, key expiry, allow-list, suspension, permissions with the PutObject mapping, bucket scope, the agent flag + Private, system bucket, the key's length); the headers it lacks (`x-amz-content-sha256`, `Content-MD5`, `x-amz-copy-source`, `If-None-Match`, `Expect`) refuse nothing for their absence. A refused POST writes no `request_log` row — exactly as a refused SigV4 request (the deferred `recordS3Access` is armed once a tenant resolved).
- **CORS at the origin:** success (201) carries `Access-Control-Allow-Origin` + `Expose-Headers: ETag, Location` from the bucket's rule; the pre-auth refusal (`applyS3CORSPreAuth`) and the post-auth one (`EntityTooLarge`) carry it too.
- **The edge otherwise:** `rebuiltBody`'s `new Request(request, {body, duplex: "half"})` after the original body was locked raises no TypeError in workerd (the lab: all 100,000 bytes reached the origin, 200; the Fetch spec's unusable-body check applies only without `init.body`); a Content-Length larger than the body aborts the backend PUT (`Network connection lost`) and commits nothing; the reaper branches on `row.Op == put` and releases + queues a form's row like a PUT's; `countEdgeAdmit` counts every outcome under `op="post"`; the mirror leg is teed (the prod row has `mirror_leg`).
- **Part 0, RP92-1:** every house writer is guarded — `SetHouseTx`, `GrantRecorded`, `Extend`, `Resize`, `StartCheckout`, BTCPay's `grantSettled` → `GrantRecorded`, the manual payment, `AdjustEntitlement` → `SetHouseTx` (a re-lived `lapsed_at` rolls back with the refusal), `applyHouse` skips; the dashboard admin's member total is a cap inside the pool, not a house. `detachOne` reduces the root's pool counter, sets the child's `pool_used = own`, deletes the 0-limit floor rows, clears `child_kind`, then `SetHouseTx` recreates the floors seeded from billed bytes — no used-bytes loss. The unguarded clearers are RP94-14/15.
- **RP92-2:** no e-mail change feature exists (only `email_verify.go` writes `users.email…`), so `OwnRootTenant`'s join on `tenants.email` cannot drift; OAuth and password registration both go through `CreateUserWithTenant`, which writes `tenants.email` and the owner `tenant_members` row;
