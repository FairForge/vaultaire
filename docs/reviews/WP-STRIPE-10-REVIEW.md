## Cleared (the attacks that did not hold)

- **The repair path**: a copy row's `etag` is the MD5 of the bytes copied, checked against the row's single-part MD5 at copy time (`copyOne`) or the commit-verified body MD5 (the edge); a head row's copy survives displacement for its version; chunk copies have `bucket = ''`; `putSinglePartIfSmall` buffers the body, so the `verifyingReader` fails before any byte reaches the backend; a multipart repair never reaches Complete on an error; `local`'s Put is atomic. (The side find is RP96-9.)
- **Chunk verification**: `sealChunk` hashes `nonce‖ct`, exactly the stored bytes; compressed-then-sealed hashes the ciphertext of the compressed bytes; a codec chunk's scope is the tenant, so the cross-tenant key case cannot arise.
- **Scope**: `blob_scrub` is `NoInherit`, so `Enabled(child)` = own row else global, which is what the SQL list and the helper's `IN ($1,'*')` read; a per-tenant OFF under a global ON skips whole/version rows and still reads shared chunks.
- **Concurrency**: `stillNamed` compares `storage_key` AND `backend_name` (chunks: `ready AND NOT marked`); a demotion flips `backend_name`, `key_reencrypt` re-points `storage_key`, displaced and retired blobs sit at addresses the walk never lists, a Complete retry re-PUTs identical bytes; no writer changes bytes under an unchanged row but the repair itself.
- **Two slots**: `execute` releases the advisory lock after `recordJobFinish`, so the result is written under it; an interrupted run writes no result, and the next slot resumes from the last committed cursor — re-reads, never skips.
- **The walk's SQL**: an index scan on the primary key with the tenant list, keyset and `ORDER BY` of one collation; chunked heads excluded by `NOT is_chunked`, chunked versions by `backend_name`; NULL `storage_key` resolves to `<key>`; `RetainedVersionsFrom` excludes the head's own blob. A global ON over millions of rows would want `(backend_name, tenant_id, bucket, object_key)`.
- **Findings/erasure/export/sweep**: the erase rule, the export exclusion and the sweep exclusion are present and covered by the schema-walk tests.
- **Metrics**: one primary-key lookup per scrape under 2 s; the cycle gauge is a per-process constant, identical on both slots; `increase()` across a slot switch contributes 0; `scalar()` of an absent series is NaN (never fires).
- **Logging**: `tenant_id` / `bucket` / `key` at Warn matches `routing_truth.go`'s and the parity scrub's practice.
- **Part 0 on the origin**: RP94-3 the refusal carries the pre-auth `Access-Control-Allow-Origin` from every bucket of that name exactly as `applyS3CORSPreAuth`, the commit the caller's own rule; RP94-4 a wrong CRC32 is refused by the PUT path's checksum wrap; RP94-6 the day cap and the minute pace both still gate a new client; RP94-13's count half is per kind and its delete half rightly open (migration 120's index is kind-blind); RP94-14 a true skip (the row lapses, no quota touched); RP94-15/16/7/8/9/10/12 as described.
- **The Worker**: the hold is `len(delim) − 1` bytes and the total enqueued is exactly `size`; a legal RFC 2046 epilogue is refused by BOTH sides (they agree); the prefix is re-prepended byte-exact on a pass-through; a chunked body with no Content-Length is the origin's 411 on both; `post-tail` is read only by `edgeAdmitPost` and every admitted form runs `fileStream`; proof → hold → backend 2xx → `moveBody` → commit, in that order; the scan is O(n) with a bounded window; `*` + credentials never emitted.
