## Call graphs

Container is always `<tenantID>_<bucket>` (`tenant.NamespaceContainer`), tenant from the credential only (`s3.go:286,367-434`).

**PUT, plain (≤64 MB, or chunking disabled by tier/versioning/flag)** — `handlePutObject` (`s3.go:743`) → quota `CheckAndReserve(declared)` → `HandlePut`: head row read (lock + If-Match) → `resolvePutStorageClass` (3 bucket reads) → body = [`awsChunkedReader`] → `countingReader` → `TeeReader(md5)` → [SSE: `io.ReadAll` + encrypt] → **backend write** (`bucketRegionDriver` direct, else `engine.Put` = `[target, primary, durable…]` walk; `objectBackends` + async `object_locations`) → `atomicHeadUpsertReleasing` (tx: `SELECT … FOR UPDATE`, release displaced manifest, upsert head row) → `object_versions` UPDATE + INSERT (outside tx, errors ignored) → `applyObjectLockOnPut` → 200 → notify/event → `settlePutQuota`. *Crash windows:* after the backend write, before the upsert → new bytes under the old head row (R2-05 class; a retry heals). After the upsert, before `object_versions` → head row newer than the version ledger (R4). After 200, before settle → reservation stays charged until reconcile (5 s detached ctx).

**PUT, chunked (>64 MB, `auto`/standard bucket, unencrypted body, flag on)** — same prefix, then `handleChunkedPut`: `ChunkContext` (goroutine, chan buffer 10) → dispatcher: per chunk `LookupChunk` → dedup hit `IncrementRef` / new → pool `submit` (8 workers: compress → encrypt → `storeChunkLocked` = tx{advisory lock, **backend write** `_global/_chunks/{hash}`, `InsertChunkTx`, commit}) → `join` → length check → `atomicHeadUpsert` (tx: `ReplaceObjectManifestTx` + head upsert) → stale blob `engine.Delete` → versions → lock → 200. *Crash windows:* mid-stream → refs compensated by the deferred `DecrementRef` (F10) on a cancellation-immune ctx; blobs with zero refs swept by GC. After manifest commit, before the stale-blob delete → orphan blob (never served). Manifest and head row are one transaction (verified `:1243-1278`).

**GET, plain** — `HandleGet`: [`?versionId` lookup] → [delete-marker lookup on versioned buckets] → head row read → smart-promotion → `HintBackend` → touch goroutine → conditionals → [chunked branch] → `engine.Get` (`[hint, primary, all]` walk) → [decrypt = `ReadAll`] → headers → Range: native `GetRange` (now skipped for encrypted) or `serveRange` → `io.Copy`. Errors after the first byte: the body is cut and Go closes the connection when `written != Content-Length` (`net/http/server.go:1733`), so the client sees a short read, never a clean 200.

**GET, chunked** — `handleChunkedGet`: `GetObjectChunks` → preflight `LookupChunk` × n (no bytes yet) → byte plan (range trims to overlapping chunks) → prefetch goroutines (≤ `CHUNK_GET_PREFETCH` slots; per-index buffered chans) → writer in index order; first chunk verified before headers (corrupt → clean 500); later failure → body aborted (short read, connection closed). Verified by reading `:1651-1748`.

**HEAD** — `handleHeadObject`: one `object_head_cache` read → headers. Backend touched only by the documented `RestoreStatus` passthrough for GLACIER-class rows (`s3.go:701-713`). No conditional, no Range, no `?versionId` handling (R2-11).

**DELETE** — `HandleDelete`: [lock check — now first] → versioned: `DELETE object_versions` (204/404) or marker INSERT + head `DELETE … RETURNING` + quota release; else head row read (`is_chunked`, `backend_name`) → chunked: `DeleteObjectChunks`; plain: `HintBackend` + `engine.Delete` (`[recorded, primary]`; unavailable → 503 and the head row stays; miss → falls through) → head `DELETE … RETURNING` → quota release → 204. *Crash between backend delete and head delete:* HEAD 200 / GET 404 until the client retries (idempotent, verified live: second DELETE → 204).

Nothing is globally bounded: peak = per-request bound × concurrent requests. A 64-request burst of chunked PUTs can reach tens of GB; recommend a server-wide semaphore on the chunked and SSE paths (WP-R2-6).

## Invariants confirmed

- **ETag:** MD5 of the decoded stream (`:657-658`), computed after the driver consumed it; PUT/HEAD/GET/List agree (live, all four sizes); 0 B → `d41d8cd98f00b204e9800998ecf8427e` and only 0 B produces it (the hasher sees exactly the bytes the backend got; drivers that fail to consume return an error, never success — R7 to keep). Chunked and dedup'd objects return the whole-object MD5.
- **HEAD from `object_head_cache` only** — the single query at `s3.go:654`; the GLACIER `RestoreStatus` passthrough is the documented exception.
- **Streaming:** the plain path never buffers a body in the API layer; buffering sites are exactly the table above.
- **Context and errors:** every DB/engine call on these paths takes `r.Context()` (the touch goroutine and quota settle deliberately detach); engine errors are wrapped with container/artifact.
- **404 vs 503 precedence:** GET, PUT, DELETE check `ErrAllBackendsUnavailable` before `isObjectMissingErr` (`:351`, `:875`, `:1900`); `isObjectMissingErr` refuses anything wrapping the sentinel (`not_found.go:38`). CDN now the same (this PR). `ErrArchived` → 403 `InvalidObjectState` / 503 for smart-demoted.
- **Chunked GET never serves bad bytes:** SHA-256 per chunk before write; no fallthrough to the plain path (`:335-347`).
- **Quota:** reserve-before-write, release on every non-2xx (live: aborted PUT released), overwrite releases the displaced size captured under `FOR UPDATE`; concurrent same-key PUTs bill exactly (arithmetic walked); chunked objects bill the measured logical size.
- **Head-cache writers all write `backend_name`:** `s3_engine_adapter.go:931,1258` (PUT plain/chunked), `s3_copy.go:227,453`, `s3_multipart.go:524`, `smart_demotion.go:352`, `smart_promotion.go:188,284` (UPDATE routing), `s3_batch.go:173` / `:1843,1927` / `account_deletion.go:159` (deletes), `s3_tagging.go:166,202` (tags only), `cmd/dedup-migrate/main.go:310`. Verified by grep; every INSERT carries the column.
- **Tenant scoping — query sites in scope, all keyed by the context tenant** (`t.ID` from `tenant.FromContext`, set at `s3.go:430` from the credential): `s3.go:654` HEAD; adapter `:219,245,280,306,621,684,929/931,979-992,1243-1276,1312-1324,1784-1812,1827-1846,1878,1926`; placement `:1953,1982,2009,2056`; `quota_accounting.go:147`; `s3_errors.go:310,354-362` (suggestions); `cdn.go:33` (slug lookup — public by design), `:43`, `:77`. Engine calls carry `common.TenantIDKey` (`s3.go:368`) and the CDN sets it explicitly (`cdn.go:120`). No path reaches the engine with an empty tenant from the S3 router: `handleS3Request` refuses unauthenticated requests before dispatch, and the `tenantID == ""` → `"default"` branch at `s3.go:394` is unreachable in non-test mode (auth errors return first). R6-22's engine-side refusal remains the right belt (WP-R6-1).
- **Placement:** `PUBLIC` resolves only from `publicBucketStorageClass` (public-read + r2 registered) — and, after this PR, never from a client header; region-pinned PUT writes the head row, versions and quota identically to the engine path (same code after `:868`).
- **Chunking flag** read per PUT (`chunkingEnabled`, `:1034`); manifests self-describe so GETs are unaffected.
- **Go short-write rule:** a handler that declares `Content-Length` and writes fewer bytes gets the connection closed (`net/http/server.go:1733`), so every mid-stream failure is detectable by the client.
