## Invariants confirmed

1. **Identity on every JSON API comes from the JWT** (`requireJWT`): `/api/v1/manage`, `/api/v1/user`, `/api/v1/webhooks`, `/api/v1/events`, `/api/v1/sts`, `/api/v1/admin`, `/api/compliance`. No handler in scope reads a tenant or user id from the path, query, body or a header, except the admin-only flag endpoints (`tenant_id` = the override target, by design) — R5 invariant 1 holds after the RBAC stub's removal (the only header-derived identity is gone).
2. **Every tenant-owned query in scope carries `tenant_id = $n`** (buckets list/get/patch/delete/tier/residency, objects list, webhooks CRUD, deliveries via `EXISTS(… id AND tenant_id)`, events list + count, idempotency rows, exports by `user_id`), and key operations go through `findOwnedKey(userID, keyID)` before any write.
3. **Secrets are shown once**: `POST /keys` and `POST /user/apikeys` return `secret`; both list endpoints strip it (`ListAPIKeys` blanks `Secret`; `Hash` is `json:"-"`); `POST /webhooks` returns `whsec_…` once and the list omits it; STS returns `secret_key` once. The account export selects no secret column. Caveat R11-08: the idempotency cache keeps the create-key response body for 24 h.
4. **STS can only narrow** (R5 invariant 4, re-verified after #512/#515): `intersectPermissions` (`*` parent → requested, else set intersection), `intersectBucketScope`, tenant fixed from the JWT, TTL clamped 1 s–12 h, ASIA keys cannot reach `/api/v1/sts` or any key route. After R11-03 the parent is the account authority or a named owned key — still never wider than the caller's own. IP widening (R5-10b) remains open.
5. **Pagination clamps**: `limit` 1..100 (default 20) on every list; `starting_after` on unique `name`/`id` for buckets/objects/webhooks; `cursor` on `created_at` for events/deliveries (R11-12 caveat).
6. **The management error envelope never carries SQL or stack text**: every `writeManagementError` message in scope is a literal; DB errors are logged and replaced (`db_error`/`internal_error`). The exceptions were `patterns.go` (deleted), the user-API key routes and the STS `scope_error` (`err.Error()` from `GenerateSTSToken`, which today is only the intersection/validation messages) — R11-17/22.
7. **Admin gate** = JWT + `users.role = 'admin'` per request (`requireAdmin`); `updated_by` on flags comes from the JWT email, never the body; unknown flag keys are 400.
8. **Rate limiter and idempotency are keyed by the JWT tenant only** — no `X-Forwarded-For`, `X-Tenant-ID` or IP is read anywhere in scope (the header-trusting `ExtractTenant`/`RateLimitMiddleware` were dead and are deleted).
9. **Webhook target policy after this session** = R4's on both entry points: http/https only, no userinfo, not `localhost`, not a literal private/loopback/link-local/CGNAT/multicast address; resolved addresses re-checked at dial time; no redirects; no environment proxy. Residual accepted: the box's own public address and `stored.ge`/`stored.cloud` hostnames are ordinary public targets — a POST there from the box is what any internet client can do.
10. `audit_logs.user_id` is `UUID` and `users.id` is `UUID` (006) — the writer parses and NULLs anything else; `tenant_id` is `VARCHAR` like `tenants.id`.
