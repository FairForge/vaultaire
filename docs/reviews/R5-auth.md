## Tenant isolation invariants

R15 re-verifies each; R11/R12 may rely on them.

1. **Tenant identity comes only from a credential.** For the S3 API it is the row matched by `tenants.access_key`, `api_keys.key_id` (→ owner's tenant) or `sts_tokens.access_key` (`auth/handlers.go:156-252`), or the presigned credential (`api/s3_presign.go:80-143`). No S3 or management handler reads a tenant/user ID from the path, query, body or a header: the only request-supplied `tenant_id` fields are on admin-only endpoints (`admin_flags.go:42,67`, the smart-demotion admin trigger, the dead `quota_management.go`), and the `X-User-ID` header feeds only the RBAC stub (R5-08).
2. **Tenant is carried in context, not re-derived.** `handleS3Request` sets `common.TenantIDKey` and `tenant.WithTenant` (`s3.go:367-428`); handlers use `tenant.FromContext` and namespace containers as `<tenantID>_<bucket>` (`tenant.go:73-77`). Test mode (`s.testMode`) has no env toggle and is set only by tests.
3. **Every tenant-owned row is read/written with a tenant predicate or after an ownership check on the same row.** Swept 392 `WHERE` clauses across `internal/{api,auth,dashboard/handlers,usage,billing}`; the ones without a tenant/user predicate are: multipart part/complete/abort updates keyed by `upload_id` — each preceded by `WHERE upload_id = $1 AND tenant_id = $2` (`s3_multipart.go:144,297,592,639`); webhook delivery queries keyed by `webhook_id` — preceded by `EXISTS(... id AND tenant_id)` (`webhooks_routes.go:336,423`); `account_exports` status updates by id after a tenant-scoped insert; the CDN slug→tenant lookup (`cdn.go:34`, public path by design); credential lookups (invariant 1); background jobs that iterate all tenants by design (dedup GC, smart demotion/promotion, inventory, access-log delivery, STS/session/idempotency cleanups); admin dashboard pages behind `RequireAdmin` (`dashboard/router.go:315`); Stripe webhook updates keyed by Stripe ids; the dead `api/middleware.go`.
4. **Scoped keys and STS tokens can only narrow the owner's authority.** Permission and bucket checks are centralised in `handleS3Request` (`s3.go:326-386`) for every operation, including CopyObject's source after this session's fix (R5-02); the tenant is fixed by the key's owner. STS mints under the JWT's tenant only; ASIA keys cannot reach `/api/v1/sts` or key management (both JWT-only).
5. **Dashboard sessions bind user + tenant at login** (`router.go:441-448`, `:659-666`, `:520-527`; OAuth `oauth.go:150-157`); every dashboard query uses `sd.UserID`/`sd.TenantID`; per-session revoke first lists the caller's own sessions (`sessions.go:9-37`). Sessions are 256-bit random, cookie `HttpOnly; Secure; SameSite=Lax`, DB-backed with `expires_at` enforced in the `UPDATE … RETURNING` read; a fresh token is minted on every login (no fixation); password change/reset revoke other/all sessions.
6. **Management APIs take identity from JWT claims only** (`requireJWT`, `server.go:1216-1237`) — `/api/v1/manage`, `/api/v1/user`, `/api/v1/sts`, `/api/v1/webhooks`, `/api/v1/events`, `/api/compliance`, `/api/v1/admin`. `/api/v1/admin` additionally checks `users.role = 'admin'` in the DB (`quota_management.go:37-55`); `/admin/*` requires session role `admin` + enabled MFA (`router.go:313-317`).
7. **The RBAC package is not an authority for anything tenant-facing.** Its three `RequirePermission` routes fail closed on the missing tenant context; nothing else consults it (R5-08).
8. **`api_keys` → tenant resolution is by `users.email = tenants.email`** (UNIQUE), correct only while no code path changes `users.email` (none exists; R5-16 tracks the schema fix).
9. **Cross-tenant dedup is by design content-addressed in the shared `_global` container; encrypted chunks are scoped per tenant** (R8 owns the verification; noted for completeness from `api/CLAUDE.md`).
10. **Suspended tenants are blocked at the S3 layer per request** (`s3.go:345`) after authentication and before any operation (fail-open on DB error — R5-22).

## Invariants confirmed

**Q1 SigV4.** See R5-19 and the real-client run. `parseSigV4AuthHeader` requires Credential/SignedHeaders/Signature; the payload hash declared in `x-amz-content-sha256` is bound to the body by `wrapPayloadVerification` (mismatch fails the read → 400); `UNSIGNED-PAYLOAD` and `STREAMING-*` pass through as documented; `SIGV4_ENFORCE` is not in the prod env (R1) so signatures are enforced; SigV2 and bare `AWSAccessKeyId` are rejected while enforcing.

Secrets at rest: primary and VLT_ plaintext (SigV4 needs them), `secret_hash` bcrypt kept beside; STS plaintext. No per-key rate limiting exists (only the management limiter per tenant and the CDN per-bucket limiter — R1-Q9).
**Q3 Scope** grammar: exact operation names, exact bucket names (no prefix grammar despite `auth/CLAUDE.md` wording), IP entries as exact IP or CIDR, `nil` expiry = never. Enforcement is centralised (invariant 4); `CheckIPAllowlist` now receives `clientip.FromRequest` (R1-01/R1-20).
**Q4 STS** — see R5-10; TTL clamp 1 s–12 h with 1 h default; hourly cleanup (`sts.go:103-121`, started in `server.Start`).
**Q5 JWT** — see R5-17; carried as `Authorization: Bearer` only (never a cookie); dashboard uses sessions, not JWTs.
**Q6 Passwords**: bcrypt cost 10 for users, backup codes and `api_keys.secret_hash`; login and registration responses do not distinguish unknown users (dashboard: "Invalid email or password."; `/auth/register` returns the raw `user already exists` message — enumeration on register, P3, R11); `/forgot-password` and `/auth/password-reset` return the same message either way ✔ (timing differs by one bcrypt-free early return — negligible with the 5/min limiter).
