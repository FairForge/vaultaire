## Verdict

**HOLDS at P2.** The package is the right shape: the harness became the
pipeline every Go host runs, the Worker's JSON is the one wire, the admit
row names its host, a customer-run host is trusted for nothing, the 307
probe closed the redirect question with evidence, and host=slc proved on
prod that the origin's own path writes the Worker's rows and meters once.
Every RP72 fix landed with its test. Three P2s remain, and none is in the
pipeline itself: **a node installed as DEPLOY.md says cannot authenticate**
(the peer rule meets Cloudflare — RP74-1), **the edge-call gate now costs an

(RP74-3). Four P3s are host=slc's and the node's own bounds. The three P2s
and four P3s are Prompt 48's Part 0, RP74-2 first.

| **RP74-1** | P2 | **A node installed as the docs say never authenticates.** DEPLOY.md § Data nodes and `install.sh`'s usage line point the node at `https://stored.ge`, which Cloudflare proxies (`docs/CLOUDFLARE.md`: every A record proxied but `s3.stored.ge`). ## The residuals and open questions, re-checked

- **RB5-1** (the Worker 0.4.1 built, not deployed): stands. Deploy 0.4.1 before 0.5.0's mirror touches `index.js` again, or fold both — Prompt 48's Worker step says which.
- **RB5-2** (a BYO node reports the client's IP) → widened by RP74-8: the pass-throughs are the node's IP for every call.
- **RB5-3** (no node without the release key): stands; the first node's VPS number comes with the ceremony.
- **RB5-4** (the pass-through's Host at the origin) → RP74-1 is the sharper form: not the hostname but the peer rule; the control-plane URL must be DNS-only.
- **RB5-5** (the Go host's PUT is not retried) → open question 1 below.
- **RB5-6** (the isolate budget couples requests): stands, dark. **RB5-7** (a node reads no window): stands — a node serving a large GET single-stream is the node's own line, not SLC's; fine. **RB5-8** (no per-tenant page): stands by policy. **RB5-9** (the edge routes mount only with the service token): stands; a deployment with nodes and no Worker sets a token nothing presents. **RB5-10** (no access log on a node): stands; the control plane's rows are the record.
- **Open question 1 (RB5-5, the single PUT):** split it. A sealed chunk is in memory on the host: retry its PUT once on a fresh connection exactly as the driver does (`FIXED_BUCKET_PUT_TIMEOUT`'s rule), because the bytes are replayable. A mover's streaming body is not replayable: the client's 503 is right, and the client retries (aws-cli does, per part). Teach `SealAndStore` the retry; leave `move` as it is. Say it as D-EDGE-45.
- **Open question 2 (D-EDGE-38's double meter):** keep both. A customer-run host is the customer's own; a fallback it reports is metered at the admitted span because it holds the link, and the origin's serve is metered because the origin served — the customer pays once for each thing that could have moved bytes to them. Say it on the DEPLOY.md BYO paragraph and in the API docs' egress section so it is never a surprise on an invoice.
