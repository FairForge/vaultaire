## Quota ledger

Contract: `tenant_quotas.storage_used_bytes == SUM(object_head_cache.size_bytes)` per tenant in **logical** bytes; with floor rows, `tenant_floor_quotas[f] == SUM(… WHERE floor = f)` and total == sum of floor limits. Chunked objects bill `measuredSize` (logical) — `s3_engine_adapter.go:1395-1398,1424,1439` and `s3_copy.go:457-460,481,505`; physical bytes (`PhysicalSize`, R8-02's 0 for a reused chunk) go only to `object_metadata`, never to `tenant_quotas`, so dedup and the R8-02 attribution cannot reach a bill in either direction. All sites go through `reserveQuota`/`releaseQuotaOn` (`quota_accounting.go:44-58`), which pick the floor-aware pair when the manager is `*usage.QuotaManager` (always, in prod); tenants without floor rows are enforced on the total only at every site (`floor.go:224-229`) — consistent.

**Race, two concurrent PUTs that each fit but not together:** `CheckAndReserveFloor` opens a transaction, `SELECT … FROM tenant_quotas WHERE tenant_id = $1 FOR UPDATE` (`floor.go:212-214`), so the second writer blocks on the row lock and, under READ COMMITTED, re-reads the row **after** the first commits (PostgreSQL re-fetches the locked row version) — it then sees `used + bytes > limit` and returns false. The floor row is read without its own lock but only ever written under the total's lock (every writer — `SetHouse`, `ReleaseFloor`, the reconcile — updates `tenant_quotas` first), so it is consistent. Proven by the new `TestCheckAndReserveFloor_ConcurrentWritersSerialize` (32 goroutines × 1 MiB against a 16 MiB floor → exactly 16 succeed, ledgers equal 16 MiB). It is a lock, not a conditional `UPDATE … WHERE used + $1 <= limit`; both are DB-level guards — the lock is what lets the floor and the total move in one transaction.

**Floor consistency / drift:** total and floor can drift from each other only via (a) admin edits of the total (R10-21), (b) the two-statement reconcile (fixed), (c) the SetHouse seeding window (R10-19), (d) the post-commit releases (R10-17/43). Reconcile heals both ledgers from the same source (`object_head_cache`), so drift is bounded by one reconcile.

## Invariants confirmed

1. **Hard quota on every write path** — plain PUT, chunked PUT, multipart complete, both CopyObject paths reserve before the write and refuse with 403 `QuotaExceeded` (ledger table); a rejected write reserves nothing (`TestFloorAccounting_FullFloorRejects`).
2. **Floor and total move together** — `CheckAndReserveFloor`/`ReleaseFloor` update both ledgers in one transaction under the total's row lock; concurrent writers serialise (new test).
3. **Logical bytes are billed** — chunked/dedup objects charge `measuredSize`; physical bytes never reach `tenant_quotas`.
4. **Delete releases exactly once** — `DELETE … RETURNING` under the row lock; a re-DELETE finds no row and releases nothing.
5. **Every release lands on the floor the head row recorded**, including overwrites that change floor (`TestFloorAccounting_OverwriteMovesBetweenFloors`).
6. **Tenants without floor rows keep the single total** at every enforcement site (`floor.go:229`); `TestFloorAccounting_LegacyTenantUnchanged`.
7. **Reconcile heals both ledgers from one source** (`TestFloorAccounting_ReconcileRepairsFloors`) — now atomically.
8. **No metered path can bill at launch** — envs unset in prod; every launch tenant with tier `standard` has floor rows and is excluded (`metered.go:151`).
9. **Stripe checkout URLs come from `VAULTAIRE_BASE_URL` only**; prices are verified against `prices.json` before checkout opens (`VerifyHousePrices`, 5-minute retry, hourly re-check).
10. **The webhook grants a house regardless of the `quota_checkout` flag** (`flags_wiring.go:34-35`) and clears it only for the tenant's current subscription id.
11. **Free-tier defaults** — `tenant_quotas(tenant_id)` INSERT relies on 034/056 defaults (tier `free`, 5 GiB); `signups` off blocks all three registration paths at `CreateUserWithTenant` (`auth.go:314`).
12. **Export never includes secrets** (`account_export.go:45,124,234-236`).
