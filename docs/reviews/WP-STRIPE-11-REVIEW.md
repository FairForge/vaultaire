## Cleared (the attacks that did not hold)

- **The dial guard**: v4-mapped loopback is caught (`To4`), `0.0.0.0/8`, CGNAT, link-local / metadata and ULA are covered; `Proxy: nil`, `CheckRedirect`, the default verified TLS; the SDK sends `Accept-Encoding: identity`; the create-time probe is the same client; `transferAllowPrivateTargets` is set only in tests.
- **A cut multipart copy** leaves nothing: the upload is aborted on a detached context, `reserved_bytes` 0 and quota used 0 after three cut runs.
- **Idempotency**: D-XFER-5's second rule includes the destination bucket and compares `dest_etag` to the CURRENT head row; a source equal to the destination skips, no loop.
- **State and races**: `transferEndSQL` and `pause` carry the state predicate — `completed` cannot overwrite `cancelled`; resume is `WHERE state = 'paused'`; every job write runs under the tenant's session lock.
- **The key**: nulled in every terminal statement; AAD tenant ‖ job ‖ version with the version recorded; the wrap test's log assertion is real; the job path stores only the source's `<Code>`; the idempotency cache keeps a digest and a redacted answer, the request log no body, the audit row and the event no key or key id; the dashboard never re-renders the secret.
- **Roles, tenants, IDOR**: `requireCaller` → `requireMember` → `requireRole(ActionTransfer)` on the three writes (viewer, developer, a management key, an agent, an `sk_test_` key: 403); the dashboard's three POSTs in `dashboardWrites` under the one CSRF middleware; the active tenant on both surfaces and the bucket looked up in it; every load `WHERE id AND tenant_id` (another tenant's id, a malformed UUID: 404); Private from `ssec_required` and Vault from the write path's own decision.
- **Quota**: every cap's refusal is `QuotaExceeded` and pauses the job; a suspended tenant is refused.
- **Erase / export / sweep / produce**: both tables erased by tenant, the export without any key column, the produce row truthful.
- **The ranged scrub (RP96-2's proper fix)**: the saved MD5 state is the state at the saved offset — a cut mid-piece at 1,500 then 2,200 of 5,000 bytes gave one `ok`, 0 findings, 5,000 bytes counted once (fork C's probe; the worker's test cuts only at piece edges); a sealed blob's expected length is carried in the resume record; the pin is compared trimmed and lower-cased; `crypto/md5`'s `MarshalBinary` is toolchain-stable and an undecodable state restarts from 0.
- **RP96-6 / the ledger / migration 126**: a backend skipped for ever gets a started timestamp; the two arms cannot both fire; `scalar()` of an absent series is NaN; no capacity run = 0 for a metered account, a NULL multiple unmetered, regions summed into the account; every key column of the unique index is NOT NULL, the dedupe is guarded and re-runnable, `ON CONFLICT` targets the index exactly, the old slot's duplicate insert is a note.
- **RP96-9's lifecycle**: a sealed copy is retired by DELETE and overwrite like a plaintext one; one with a multipart backend ETag is copied size-checked and never used for repair.
- **RP96-10 / RP96-19 / RP96-20**: the guards run before the statement and a no-op still writes the audit row; the pre-limiter is keyed on `clientip` (/64 for IPv6), ahead of the body and the database, evicting oldest past 20,000; the line's cache key is tenant + bucket under a mutex, an error cached as "no line", never a line.
- **The Worker's other direction**: every disposition the regex does not fully consume goes to the origin whole; `cors_origin` comes only from the admit's JSON, with `Vary: Origin` and never credentials; the `IncompleteBody` catch swallows nothing else (an origin 503 is relayed).
