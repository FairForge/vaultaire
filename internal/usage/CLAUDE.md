# internal/usage

Quota and allowance bookkeeping in PostgreSQL. Everything here is in LOGICAL bytes.

## Files

- **quota_manager.go** — `QuotaManager`: `tenant_quotas` (the single total quota). `CheckAndReserve` / `ReleaseQuota` are the WP-1 reservation pair (`SELECT … FOR UPDATE`, one transaction; no `quota_usage_events` row since WP-R10-8 — `GetUsageHistory` is `bandwidth_usage_daily`); `ReconcileStorageUsage` / `ReconcileTenantStorageUsage` rewrite usage from the billed bytes (never call the global one from a test — the test database is shared).
- **ledger_tx.go** — WP-R10-8: `ApplyLedgerTx(ctx, tx, tenant, LedgerChange)`, the ledger inside the caller's transaction (the flip's settle, every delete, the upload's parts): the total's row locked only when the total moves, floors after it (standard, then vault), clamped at 0, an optional `Guard` that refuses (`ErrOverQuota`) a change that ends past a limit. The lock order is in its file comment.
- **billed.go** — what is billed (WP-R2-1 C2): every head row plus every RETAINED non-current version, plus every ACTIVE multipart upload's `reserved_bytes` on `UploadHoldingFloor` (WP-R10-8, 091); `BilledBytes(ctx, tenant)` reads what the reconcile would write (tests compare the ledgers with it) (`RetainedVersionsFrom`: `storage_key` set, not a delete marker, not the head row's own blob — the latest version is counted once, as the head row), on `RetainedVersionFloor` (the version's `floor` (088), else the head row's, else vault on `geyser`, else standard). The reconciles and `SetHouse` read the constants built from them; `internal/api` (gauge, version delete) and the dashboard use the two exported fragments. Metered reporting reads `tenant_quotas.storage_used_bytes`, so it reports version bytes too.
- **floor.go** — the house: `tenant_floor_quotas` (066), one row per (tenant, `standard`|`vault`). `SetHouse` / `ClearHouse` are idempotent, and their bodies are `SetHouseTx` / `ClearHouseTx` on a caller's transaction (WP-PAY-1: `internal/payments` writes the entitlement record and the floors in one — the Stripe webhook and the dashboard resize go through it since 097; the total is locked before the floors in both); `ReserveOnFloor` (`Reservation{OK, Floor}`: whether the floor row was charged too) / `ReserveTx` (the same rule inside a caller's transaction) / `CheckAndReserveFloor` / `ReleaseFloor` move the total and the floor together; a new floor row is seeded by the reconcile's computation (uploads included); `FloorOf(storageClass)` decides the floor of a write. `TB` = 2^40.
- **free_tier.go** — `FreeTierLimits` (5 GiB, 1 bucket, 1 API key).
- **egress.go** — the egress allowance (WP-R10-9), **the one definition** read by the throttle and the alerter (`internal/api/egress_meter.go`, `bandwidth_alerts.go`), the dashboard overview, the admin tenant page and `/api/v1/user/usage`:
  - `QuotaManager.EgressAllowance(ctx, tenantID)` — derived at read time, one query. Precedence: admin override (`tenant_quotas.bandwidth_limit_bytes > 0`) → the house (Standard ratio × the `standard` floor limit + Vault ratio × the `vault` floor limit) → no house (Standard ratio × `storage_limit_bytes`; the free tier's 5 GiB gives 2.5 GiB). Ratios come from `prices.json` through `landing.Get()` (`EgressRatios`). Nothing is seeded: `SetHouse`/`ClearHouse` never write `bandwidth_limit_bytes`, so an override survives a webhook replay and the end of a subscription. Override 0/NULL = the plan's allowance (not "unlimited" — exempting a tenant is a per-tenant `egress_throttle` flag row).
  - `EgressMonthStart` / `EgressResetAt` — the month is the **UTC calendar month** for every reader; `MonthEgressBytes` sums `egress_bytes` only (uploads never count — Review R13-16).
  - `EgressThrottle` (`DefaultEgressThrottle`, `Rate`) — the D-25 knobs: `max(MinBytesPerSec, Factor × allowance / 2,592,000 s)`, `MaxStreams`.
  - `EgressStatus` / `EgressStatusReader` / `EgressStatusFromDB` / `EgressOver` — a tenant's position this month; the API server's live counter implements the reader, `EgressStatusFromDB` is the same answer without responses in flight.

## Tests

DB-backed against `vaultaire_test` (`make test-db`); each test creates its own tenant (`newTestTenant`) and touches only its rows. `egress_test.go` pins the ratios to `prices.json` and the override-survives-SetHouse/ClearHouse requirement.
