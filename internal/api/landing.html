3-2-1 backups that actually finish

Point restic, rclone, or any S3-speaking backup tool at a bucket. Encrypted client-side if you want, versioned server-side if you ask.

  • No minimum storage duration — rotate nightlies without penalty fees
  • Bucket versioning + Object Lock stop ransomware from rewriting history
  • Add a Vault pack as the off-site deep copy — it bills separately, so it survives budget cuts

  • Webhooks fire on object.created — trigger thumbnails, virus scans, pipelines

04Attach anything

If it speaks S3, it plugs in.

Tools, SDKs, and platform features all hit the same endpoint with the same keys — mix them freely on the same bucket. Click around.

rclonesync · mount · migrate

The Swiss-army knife: sync directories, mount buckets as drives, and migrate straight off B2/S3/Drive into stored.ge with one command. Full walkthrough in the rclone guide.

shell
rclone config create stored s3 provider=Other \
  access_key_id=YOUR_KEY secret_access_key=YOUR_SECRET \
  endpoint=https://stored.ge region=us-east-1

rclone sync ~/photos stored:photos -P      # keep in sync
rclone mount stored:photos ~/mnt/photos    # use as a drive
rclone sync b2:old-bucket stored:photos    # leave your old provider

resticencrypted backups

Client-side encrypted, deduplicated, incremental backups. Your keys never leave your machine — we store ciphertext and can't read a byte of it.

shell
restic -r s3:https://stored.ge/backups init
restic -r s3:https://stored.ge/backups backup /srv/data
restic -r s3:https://stored.ge/backups forget --keep-daily 7 --keep-weekly 8 --prune

aws-cliscriptable everything

Every S3 operation we support, from cron jobs and CI pipelines. Multipart, versioning, tagging, lock — it's all the same flags you already know, plus --endpoint-url.

shell
alias s3ge='aws --endpoint-url https://stored.ge'

s3ge s3 mb s3://ci-artifacts
s3ge s3 cp build.tar.gz s3://ci-artifacts/v1.4.2/
s3ge s3api list-object-versions --bucket ci-artifacts --prefix v1.4.2/

Scoped keys & STSleast privilege

Mint API keys locked to specific buckets and permissions, with optional IP allowlists and expiry. Need something shorter-lived? STS issues temporary credentials that can only narrow — never escalate — the parent key's scope.

shell — temporary credentials
curl -X POST https://stored.ge/api/v1/sts/token \
  -H "Authorization: Bearer $JWT" \
  -d '{"duration_seconds": 3600,
       "buckets": ["user-uploads"],
       "permissions": ["read", "write"]}'

Webhooks & eventsreact to storage

Subscribe an HTTPS endpoint to object.created, object.deleted, bucket and key events. Deliveries are HMAC-signed and logged with response codes, so you can actually debug them.

shell
curl -X POST https://stored.ge/api/v1/webhooks \
  -H "Authorization: Bearer $JWT" \
  -d '{"url": "https://api.example.com/on-upload",
       "events": ["object.created"]}'

06Straight answers

The parts most storage pages won't tell you.

More in the full FAQ.

Is there an SLA?

Not a contractual one yet — we won't sell one we can't back. The target is 99.5%+, the status page is real, and incident reports are written by a human. SLA credits ship with the second site.

Where does my data actually live?

On established storage providers — enterprise S3 infrastructure for hot data, professional tape libraries for archive. The control plane runs on our own hardware with tested daily off-site backups; your data doesn't depend on that one box.

How fast are cold reads?

Data that's aged to tape spools to cache on first read — seconds to a couple of minutes to first byte, longer for multi-TB restores. Hot data is <50 ms. Need everything hot forever? That's the Performance tier.

What if you disappear?

It's standard S3 — rclone sync your data out any time, free, no proprietary format. Documented wind-down commitment: minimum 60 days notice and free unlimited egress. The engine is open source, so the software outlives us too.
