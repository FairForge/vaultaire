# internal/drivers

Storage backend implementations for the Vaultaire engine. Every registered driver implements `engine.Driver` (defined in `internal/engine/interface.go`); `S3Driver` (`s3.go`) is the one exception — an embedded base type whose `Put` takes no options, so it is not an `engine.Driver` itself.

## Driver Interface Contract

```go
type Driver interface {
    Name() string
    Get(ctx context.Context, container, artifact string) (io.ReadCloser, error)
    Put(ctx context.Context, container, artifact string, data io.Reader, opts ...PutOption) error
    Delete(ctx context.Context, container, artifact string) error
    List(ctx context.Context, container string, prefix string) ([]string, error)
    Exists(ctx context.Context, container, artifact string) (bool, error)
    HealthCheck(ctx context.Context) error
}
```

All registered drivers implement `engine.Driver` directly (the old `driver.go` alias + `PutOption` shim was removed in Review R0; put options are `engine.WithContentType` etc.). `S3Driver` is only ever embedded (`QuotalessDriver`), never registered.

Metrics `vaultaire_webdav_{requests,stalls,retries}_total` (`InitWebDAVSeries`); `Stats()` for the bench. Tests `webdav_resilience_test.go`. `StoreID` `dav:<origin><root>/`. **Target-only + flag-gated** (`sync_backend`, Sync's ToS: customer data only with its written consent) — ops manual `webdav_README.md`; tests `webdav_test.go` (x/net/webdav MemFS behind Basic auth) |
| `MultiWebDAVDriver` | `webdav_multi.go` | `NewMultiWebDAVDriver(name, WebDAVConfig{Bridges, User, Root, LargeConcurrency, …}, logger, ...WebDAVOption)` | **What `sync` is registered as** (1..16 Sync bridges of one folder: `SYNC_WEBDAV_URLS` + `SYNC_WEBDAV_PASSWORDS`, or the single `SYNC_WEBDAV_PASSWORD` = one bridge) | One `WebDAVDriver` per bridge (own password, caps, retries; metrics `bridge="<index>"`). Every key on ONE bridge by HRW (`hrwRank`: FNV-1a+splitmix64 over the bridge URL id + `t-<tenant>/<container>/<key>`). Reads (`Get`/`GetRange`/`Exists`/`List`) of an unhealthy bridge (probe down, or 3 unavailable answers → 30 s breaker, or this call refused/stalled/5xx) fall back in HRW order; a fallback's miss is `ErrWebDAVBridgeStale` (wraps `engine.ErrAllBackendsUnavailable` → 503, never 404: cross-bridge staleness 1.5 s–5 min, live 2026-10-07). Writes never fail over. `WalkTenant` unions every bridge (Remove on the routed bridge; one bridge failing fails the walk). `ListDir` = one folder through one bridge; `RemoveEmptyDir` deletes only what EVERY bridge lists empty — one DELETE (a collection DELETE is recursive and the bridges share one account; `ErrDirNotEmpty`; `webdav_remove_dir_test.go`); nothing can see a write that lands between the last empty listing and the DELETE — the callers make that window empty (the parity job is the only writer and the only folder remover, under its lock; the stripe reaper removes only first-layout key folders, which nothing writes); the listing after the DELETE sees only later content, which survived (Warn, success). Large transfers (≥ 16 MiB or unknown) take one of `SYNC_WEBDAV_LARGE_CONCURRENCY` (3) slots per bridge and direction (download slot via `WebDAVDriver.bodyGate`). `HealthCheck` = every bridge, up while one is, `vaultaire_webdav_bridge_up{backend,bridge}`. **Never a server modtime** (Sync's bridge reports 1970 dates; `propfindBody` asks for none). **Striping** (`webdav_stripe.go`): a known-length Put ≥ `SYNC_WEBDAV_STRIPE_MIN` (512 MiB) is cut into `SYNC_WEBDAV_STRIPE_PIECE` (256 MiB) pieces routed by HRW on their own names under `<container>%p/<hh>/<h>-<gen>/`, staged on disk (≤ bridges × large slots), uploaded in parallel; the manifest `<leaf>%s` is written last; a manifest cache (4,096 entries, 10 min, dropped on own writes and on a piece found gone) skips the probe + manifest GET; the first two pieces of a read open at once; sha256 per whole piece; `ReapOrphanStripes` (job `stripe_gc`) removes unreferenced generations older than 6 h by their name's time. Tests `webdav_multi_test.go`, `webdav_stripe_test.go`; ops `webdav_README.md` |

### iDrive Region Registry (Phase 5.14.7)

`idrive_regions.go` — the 13 regions the reseller account actually has (`s3.<region>.idrivee2.com`; rebuilt in WP-R7-1 — the old table named eight AWS-style ids on `e2-<region>.idrive.com`, three of which never existed). `cmd/vaultaire/main.go` registers one `IDriveDriver` per region (`idrive-{region}`) **only when that region's own key pair is set** (`IDriveRegionCredentials` has no fallback — the primary pair answers 403 elsewhere), calls `EnsureBucket` so the region's fixed bucket exists, and records the enabled set with `SetAvailableIDriveRegions`. The primary serves `IDriveDefaultRegion` (`IDRIVE_REGION`, else `us-central-1`).

Helpers: `IsValidRegion`, `IsEURegion` (`eu-*`), `RegionDisplayName`, `IDriveRegionGroups` (US / EU / Asia Pacific for pickers), `IDriveRegionAvailable` (enforced once main.go has called `SetAvailableIDriveRegions`; unset = every table region, for tests/dev). Called from S3 API (`CreateBucket` validation, `bucketRegionDriver` routing), dashboard (`HandleBuckets` picker, `HandleCreateBucket`, `HandleBucketSettings`).

| `s3list.go` | `s3ListPaginator` | The one way drivers walk `ListObjectsV2` pages (R7-06): `StopOnDuplicateToken` so a gateway that repeats a continuation token cannot spin the caller. Used by idrive, lyve, r2, geyser, s3, s3compat |
| `tenant_walk.go` | `WalkTenant` on idrive (+ regions), lyve, geyser, r2, s3compat, quotaless, local (and `sync`, in `webdav.go`: a PROPFIND walk of `t-<tenant>/`); `s3WalkPrefix`; `ErrWalkTenantID` | `engine.TenantWalker` (WP-R10-3c, the account-erasure sweep): everything ONE tenant holds on the backend, each object with a `Remove` bound to the listed key. Tests: `tenant_walk_test.go` (a paging fake with DELETE: neighbours `tenant-abc` / `tenant-a`, `X_b` vs `X_bc`, lost page, stuck token, foreign key), `onedrive_sweep_test.go` |
| `s3upload.go` | `s3ParallelUpload` | Shared parallel multipart upload via the AWS SDK `manager.Uploader` (16 MiB parts, 8 concurrent). One `manager.Uploader` is cached per client so the SDK's part-buffer pool is reused across calls. Large files upload as concurrent parts instead of one PutObject stream; small files still go as a single PutObject; no full-object buffering. **R2-06:** a body that ends before its declared size (client gone mid-upload) is an error, never committed as a shorter object. Used by the `Put` of `s3compat.go`, `idrive.go` and `r2.go`; `lyve.go` goes through the `s3ParallelUploadInput` variant (caller-built `PutObjectInput`, same uploader).
