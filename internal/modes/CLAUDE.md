# internal/modes

Keystone K3 (Stage 1a Prompt 26; plan Phase 41.0; `docs/ARCHITECTURE_CONTRACT.md` lines 1, 3, 8). The bucket's **mode** — Private / Standard / Public — and the one table that says what each lets us read.

- **The table** is `internal/api/landing/modes.json` (embedded by `landing.ModesJSON()`, beside `prices.json`): exactly three modes in the order private, standard, public — each `id`, `name`, `server_holds` (what we can read), `customer` (the customer's sentence), `how` (how a bucket gets it) — and `surfaces` (developer: standard + private; consumer: standard until F-19, then private; public: public). A sentence is `{text, requires_master_key, without_master_key}`: one marked `requires_master_key` (Standard's "encrypted at rest with keys we hold") renders only while the process has the master key; its `without_master_key` must be true on EVERY backend a Standard object can reach — `docs/BACKEND_ENCRYPTION.md` is the per-driver table it is checked against (RP33-6: Geyser has no vendor encryption on our account, iDrive's default is unconfirmed, Blomp is plain HTTP), so it says "Not encrypted by us at rest yet … encrypted there only where the provider does so" — `Sentence.Render(MasterKeyLoaded())`; `SetMasterKeyLoaded(true)` is called by `api.NewServer` once the tenant key store starts. Prod has no master key (`docs/reviews/K3-PROBE.md`): the pre-key sentence is what renders there.
- `All()` parses and `Validate`s once (a failure panics: the file is in the binary); `Get(id)`, `Name(id)`. Validation: three modes, every name and sentence non-empty, a pre-key sentence wherever one needs the key, no mode named Vault (a tier), no "zero-knowledge" anywhere. Tests `TestModesJSON_ThreeModesNoForbiddenWords`, `TestValidate_RefusesWhatTheTestRefuses`, `TestSentence_RenderFollowsTheMasterKey`.
- **The column** `buckets.mode` (migration 102) is GENERATED from `visibility` and `ssec_required`; `FromColumns` is its CASE in Go. **NAME TRAP:** `visibility = 'private'` means "not public-read" = **Standard**.
- **The one write door** `SetBucket(ctx, q, tenant, bucket, Change{Visibility, SSECRequired})` (a `*sql.DB` runs it in its own transaction; the lock is transaction-scoped): takes the **bucket-mode lock EXCLUSIVE** (`ModeLockSQL`, two-int advisory key `hashtext('bucket-mode'), hashtext(tenant/bucket)`; every commit of a row with bytes takes it SHARED — `ModeLockSharedSQL`, `internal/api/blob_flip.go`), reads the row, and on an `ssec_required` false→true change refuses **Private over anything we can read** (RP33-1, Stage 1a Prompt 27) — in a SEPARATE statement after the lock (READ COMMITTED: a subquery inside the UPDATE keeps the snapshot from before the wait): head rows whose `encryption_algorithm` is not SSE-C (`SSECAlgorithms` = `crypto.SSECAlgorithm*`; `ssec_key_md5` is not the marker — NULL on SSE-C rows before 094; a chunked row is never SSE-C), version rows that are not delete markers and not SSE-C (a version row from before 087 has no algorithm: counted, the safe side), active multipart uploads with `ssec_key_md5 = ''` → `*ReadableObjectsError{Objects, Versions, Uploads}` (`errors.Is(…, ErrReadableObjects)`; the management PATCH answers 409 `bucket_has_readable_objects` with `error.readable`, the dashboard a flash: copy into a new bucket). Then one UPDATE writes either column and refuses public + ssec (the 096 rule) — `ErrPublicSSEC` / `ErrNoBucket` / `ErrBadVisibility`; and when the mode changed, **one `audit_logs` row `bucket.mode_changed`** {bucket, from, to, visibility, ssec_required} with the context's actor, IP and user agent, IN the door's transaction (`audit.RecordTx`: the row commits with the change or neither does — RP33-4). Nothing written on a refusal; returns the new mode. Leaving Private and Standard ↔ Public are never asked what the bucket holds (Public over a non-empty bucket is F-32, the owner's). Callers (`doorCallers` in the writers test): the dashboard bucket settings (`bucket_settings.go`, with the rest of the form in one transaction), the management PATCH (`management_routes.go`), and **a create asking for `"mode": "private"`** (`bucket_create.go`, RP33-1 c — plan line 1699 "set at creation"): the row is born Standard and made Private through the door in the create's transaction (`modes.Change{SSECRequired: &opts.private}` only). Every other create (three INSERTs: `bucket_create.go`, `auth/backfill.go`, the `_exports` row) is born Standard. `DeveloperModes()` = the developer surface's modes (standard, private): what the API creates and the OpenAPI enum. `TestBucketModeWritersOnlyThroughTheDoor` reads every non-test Go file and fails on any other SQL that writes either column and on a door call from an unknown file. Tests `door_test.go` (`TestSetBucket_PrivateRefusedOverEachReadableKind`, `TestBucketModeChange_Audited`, `…_RefusedLeavesNoAuditRow`). Tests `TestBucketMode_DerivedFromVisibilityAndSSEC` (all four combinations, the refused one included), `TestSetBucket_*`.
- **Never typed elsewhere:** `internal/api/modes_copy_test.go` `TestModeNamesOnlyFromModesJSON` fails on a modes.json sentence, "<name> mode", "keys we hold" or "zero-knowledge" typed in a dashboard template, a landing source, a served guide, the OpenAPI generator or llms.txt, and on a `>Private<` / `>Public<` label — with an explicit, counted allow-list (`modeCopyAllowed`; an entry that matches nothing fails too). The legacy visibility labels of the bucket list and settings are on it until `modes_copy` renders `modes.Name`.
- **The readers (K3 PR 3)**, all generated: the management API's bucket JSON `mode` (list/get/create/patch); the OpenAPI `ManagedBucket.mode` enum + description and PutObject's four `x-amz-server-side-encryption*` header texts (`internal/docs/openapi_modes.go` — built at route setup, after the key store); llms.txt's bucket-modes line (`llmsModes`); behind **`FlagModesCopy` = `modes_copy`** (default OFF): the dashboard bucket list badge and the settings Mode card (`handlers/modes_labels.go`, `SetModesCopy` wired by the router, per tenant) and the privacy page's per-mode table (`handlers/legal.go` `privacyModes`, read GLOBALLY — the owner flips it after reading the table: a legal page). `TestFeaturesWithoutADeclaredMode_Count` (`internal/api/modes_copy_test.go`) is `docs/STATUS.md`'s convergence number — the files whose mode label is still hand-typed (the legacy branches while the flag is off): 2.
