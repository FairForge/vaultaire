# internal/translog

Keystone K4 (Stage 1a Prompt 28; plan Phase 43.6; decision F-16; `docs/ARCHITECTURE_CONTRACT.md` rule 7). The transparency log: an append-only Merkle log (RFC 6962 / RFC 9162 hashing), checkpoints as C2SP signed notes, inclusion and consistency proofs, the c2sp.org/tlog-tiles layout. Operator page: `docs/TRANSPARENCY.md`.

- **No hand-written Merkle or proof code.** Hashing, stored hashes, roots, proofs, tile contents: `golang.org/x/mod/sumdb/tlog` (v0.41.0, BSD-3). Notes and Ed25519 note keys: `golang.org/x/mod/sumdb/note`. The checkpoint body: `github.com/transparency-dev/formats/log` (v0.1.1, Apache-2.0). Proof **verification**: `github.com/transparency-dev/merkle/proof` (v0.0.2, Apache-2.0) — a second implementation, so every proof x/mod produces is checked by code it did not come from. This package is glue: ranges, origin, layout.
- **Origin** `stored.cloud/translog/v1` — the checkpoint's first line AND the signing key's name (`NewSigner`/`NewVerifier` refuse a key named otherwise). Changing it is a new log.
- **Pure:** no DB. `HashReader` (tlog's: stored hashes by storage index `StoredHashIndex(level, n)`) is the storage contract; `StoredHashes(n, body, r)` returns what appending entry n must persist, starting at index `StoredHashCount(n)`. `Memory` is the in-process reference store (tests, `translog-verify`).
- **Layout:** `checkpoint`, `tile/<L>/<N>[.p/<W>]`, `tile/entries/<N>[.p/<W>]`; N in 3-digit groups, all but the last prefixed `x`; full = 256, no `.p`. `TilePath`/`ParseTilePath` (canonical form only), `TileData` (tlog height-8 tiles: level L = tree level 8L), `TileWidthAt`, `EntryBundle` (uint16 big-endian length + bytes; entries ≤ 65535 bytes).
- Tests: `TestTranslog_KnownAnswer_RFC6962Vectors` (transparency-dev/merkle testonly vectors, sizes 0…8), `TestTranslog_InclusionProofVerifies`, `TestTranslog_ConsistencyProof_RewriteDetected`, `TestTranslog_CheckpointIsC2SPSignedNote` (opened with `note.Open`; key ID recomputed from the spec), `TestTranslog_TilePaths_C2SP`, `TestTranslog_TileData`, `TestTranslog_EntryBundle`.
- **Entries** (`entries.go`, PR 2): the log is PUBLIC, so `Entry` is sealed (an unexported method) and each kind is a typed struct with an allow-list (`AllowedFields`): `ServerBuild{git_sha, binary_sha256, build_time, go_version}` (dedup key = git sha + binary), `KeyCeremony{action (enum CeremonyActions()), key_role (enum KeyRoles()), key_fingerprint ("sha256:"+64 hex, never the key), participants, shares, threshold, signed_size, restored_size, new_origin (log_restored only), reference (a github.com/FairForge/vaultaire pull / 40-hex commit / docs file URL)}` (no dedup; `RetryableCeremony(c, key)` = the same body with a dedup key, the ceremony route's Idempotency-Key). **No free text (RP37-10):** every field is enumerated, a number or a fixed shape; the #884 `statement` is gone and `ParseKeyCeremony` / `Decode` refuse an unknown field (`TestCeremonyEntry_RefusesFreeText`: a name with an address, an obfuscated e-mail, a bare tenant id cannot be expressed). `Encode(e, at)` validates and writes `{"kind","v":1,"at","entry"}` — the exact bytes hashed; `Decode` reads one back. `TestTranslog_EntriesNeverNameATenant` reflects every kind against its allow-list and forbidden field words, and pushes identifying strings into every string field.
- **Signing key** (`keysource.go`): `LoadSigningKey(getenv, readFile)` — credential `translog_signing_key`, `TRANSLOG_SIGNING_KEY_FILE`, `TRANSLOG_SIGNING_KEY`; the master key's rules (set but unusable = `ErrSigningKeySource`, the server's Fatal; none = nil signer). `TestTranslog_SigningKeySources`. Server side: `api.translogSigningKeyOrFatal` (`internal/api/translog.go`).
- **`logstore/`** — the Postgres store (migration 103): `Append` = one transaction under `pg_advisory_xact_lock(hashtextextended('translog',0))` — dedup check, next index `MAX(idx)+1`, a guard that the stored-hash count is `StoredHashCount(n)`, the entry and its hashes inserted together; every failure counts in `vaultaire_translog_append_failures_total{kind}` (all kinds pre-created at 0). **`ReAppend(bodies, expect)`** (K4b, RP38-6, `cmd/tools/translog-restore`): the lost entries M…N−1 put back from a witness's cache — raw bodies (never re-encoded: a new `at` changes the leaf), same writes as Append, kind + dedup key from `translog.Decode` of the body (undecodable = refused), one transaction under the same lock, rolled back unless the root at `expect.Size` is `expect.Root` (`ErrReAppendRoot`; wrong count / M ≥ N = `ErrReAppendSize`); never signs. `ReadHighwater(path)` = the job's parser of the high-water file, shared with the tool. `TestReAppend_RestoresTheExactTree`, `_WrongBytes_RollsBack`, `_RefusesPastCheckpoint`, `_RefusesUndecodableBody`; `TestTranslogRestore_FromTheWitnessCache_TheJobPassesAgain`. `Size`, `Root`, `InclusionProof`, `ConsistencyProof`, `Entries`, `HashReader`, `LatestCheckpoint`; `Checkpoint` signs when the tree grew, after proving the log extends the newest checkpoint (`checkExtends`; a refusal is an error, never a signature). `StateCollector` reads size / checkpoint size / time on scrape (15 s cache). The tables refuse UPDATE/DELETE/TRUNCATE (trigger) and `TestTranslog_OnlyTheStoreWritesTheLogTables` keeps every INSERT in this package. Tests share the global log on the test DB: they check their own entries and whole-log invariants, never an absolute size (`TestTranslog_ConcurrentAppends_Contiguous` recomputes the root from the bodies alone).
- **Read side** (`serve.go`, PR 3): `NewHandler(Source)` serves `checkpoint` (text, `no-store`) and `tile/…` relative to its mount; only what the newest checkpoint commits to (a tile wider than `TileWidthAt` at the checkpoint's size is 404; a narrower partial tile — an older checkpoint's — is served); no checkpoint = 404 everywhere; full tiles `public, max-age=31536000, immutable`, partial `no-store`; GET/HEAD only. `Source` = `CheckpointNote`, `HashReader`, `Entries` — `logstore.Store` and `MemorySource` (signs its current size on every read; tests and tools).
- **Client** (`client.go`): `Checkpoint` (signature against a pinned verifier), `VerifyInclusion` (fetches the entry bundle; proof from hashes read through `tlog.TileHashReader`, which authenticates every tile against the checkpoint root; verified by transparency-dev), `VerifyConsistency` (saved checkpoint → new; same size with another root = a fork). `EntryBundle(cp, n)` (K4b) fetches bundle n at its width in cp and proves every entry's leaf hash against cp (the witness keeps the raw bytes). `Tiles TileCache` (K4b): full tiles read from it before the network, and every full tile `tlog.TileHashReader` authenticated handed to it through tlog's `SaveTiles` (a cached tile is authenticated again, so a corrupted copy is an error) — `TestTranslogClient_FullTilesFromTheCache`, `_EntryBundleProvesEveryEntry`. `cmd/tools/translog-verify` is its CLI. `TestTranslogVerify_RewrittenHistoryFails` (here and in the CLI).
- **`witness/`** (K4b, `cmd/tools/translog-witness`, never linked into `cmd/vaultaire` — `TestProductBinaryDoesNotLinkTheWitness`): `Witness.Pass` = checkpoint signature → consistency with `<dir>/checkpoint` through a READ-ONLY view of the cache (a refused tree's tiles are never kept) → mirror every full entry bundle + full level-0 tile and the partial bundle at the checkpoint's size into `<dir>/cache/<tile path>` (`Cache`, byte-exact, atomic writes; a full bundle drops the partial copies, a wider partial the narrower) → co-sign (`note.Open` with the log key, `note.Sign` with the witness's own key: both signature lines) to `<dir>/cosigned` + `cosigned.history` (a line per NEW note) → the state last. Refuses the log's own key (`ErrSameKey`). `Cache.Entries(from, to)` gives bodies back byte for byte and names a missing / too narrow bundle (translog-restore). Tests: `TestWitness_CosignedNoteCarriesBothKeys`, `_ForkRefused_StateAndCacheUntouched`, `_CachesEntryBundlesByteExact`, `_ForgedEntryBundleRefused_NothingKept`, `_RefusesTheLogsOwnKey`.
- **Server side** (`internal/api/translog.go`, `translog_read.go`): the signing key at boot, the `translog_checkpoint` job, the `server_build` entry at `Start` (background, once per binary), `POST /api/v1/admin/translog/ceremony` (admin + fresh TOTP, audited), `GET /translog/checkpoint` + `/translog/tile/*` behind `translog_public` (default OFF = 404; a signed or presigned request goes to the S3 API).

- **The high-water file (RP37-11, `logstore.WithHighwater`):** the checkpoint job keeps the newest checkpoint it signed in `TRANSLOG_HIGHWATER_FILE` (outside the database, 0600, atomic, after the row) and refuses — `vaultaire_translog_checkpoint_refusals_total{reason=rewritten|behind_highwater|highwater_unreadable}`, `TranslogCheckpointRefused` pages — unless the stored log extends both it and the newest DB checkpoint. A DB restore can no longer make the key sign a second tree at a size it signed. **The same file gates `Append` (RP42-1, Stage 1a Prompt 33):** read inside the append's transaction under the lock, on every append — behind it (`n < hw.Size`) or unreadable (garbage, another origin: RP42-6, the error names `mv … highwater.<v>`) = `ErrLogFrozen`, nothing written, `vaultaire_translog_append_refusals_total{reason=behind_highwater|highwater_unreadable}` (pre-created; NOT `append_failures_total`), `TranslogFrozen` pages; absent = first run, appends. `Frozen(ctx)` is the same verdict for a caller that must answer before it spends something (the ceremony route, before the TOTP). `ReAppend` is NOT gated (the way out). `TestAppend_BehindHighwater_Refused`, `_HighwaterUnreadable_Refused`, `TestReadHighwater_AnotherOrigin_NamesTheArchiveStep`. Procedure: `docs/TRANSPARENCY.md` § After a database restore.
- **Tests that sign use their own log (RP37-13):** `logstore/logstoretest.PrivateLog(t)` = a throwaway database with only migration 103. The shared test log is global: a test there asserts only on what it appended.
