## What it means

- **Path-style addressing is the one compatibility gap.** Every client that can be told "path style" works; Duplicacy cannot, and other tools default to virtual-hosted buckets too (Synology Hyper Backup's S3 target and some NAS clients among them — untested here). Supporting `<bucket>.s3.stored.cloud` needs: a wildcard DNS record `*.s3.stored.cloud`, a certificate covering it (Cloudflare's edge certificate covers one wildcard level per name — `*.s3.stored.cloud` must be added explicitly), the Worker passing the Host through, and the server taking the bucket from the Host when the path has none (SigV4 signs the Host, so the server must not rewrite it). A small work package; it widens compatibility more than any other single change.
- **SigV2 stays refused.** It is deprecated by AWS and weaker; the fix for Duplicacy is its `s3://` (SigV4) scheme once virtual-hosted buckets resolve.
- **Not tested here:** Arq, Cyberduck (GUI, macOS), Synology Hyper Backup, TrueNAS Cloud Sync (rclone underneath — expected to work with rclone's settings), Proxmox Backup Server S3 datastores, Veeam.
