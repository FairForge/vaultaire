# Sia via s3d — conformance + bench, 2026-10-21

The Sia network reached through **s3d** (github.com/SiaFoundation/s3d v0.2.1), the
Sia Foundation's localhost S3 gateway: client-side encryption, 10-of-30 erasure
across Sia hosts, paid by the sia.storage account the gateway is registered to.
Account: partner@fairforge.io, **free plan (50 GB)** — all numbers below are on it.
The `sia` driver (PR #825) is `NewFixedBucketS3Driver("sia", …)` against this
gateway.

## Why this exists

Decentralized-backend re-check of 2026-10-21: Solstice (FIP-0118, NV29,
activated ~2026-10-19) deprecated Filecoin Plus DataCap in full — free verified
deals are dead (every new sector gets 10× QAP regardless of content, the service
reward stream pays only Filecoin Pay settled volume). The cheapest surviving
decentralized S3 is sia.storage: Pro $14.99/mo = 5 TB (~$3/TB-mo), Unlimited
$19.99/mo = 10 TB + $4.99/TB over (~$2/TB-mo at 10 TB). Filecoin's remaining
play is the paid Onchain Cloud (~$5/TB, 2 copies, PDP) — proof tier only.
Nothing here beats Geyser's $1.55/TB on cost; this is the privacy/decentralized
story, not a COGS play.

  non-interactive auth yet, s3d #306); the same seed registers any number of
  instances (the Mac lab at `~/fairforge/s3d-lab` shares it).
- **Lab Vaultaire**: binary from main `9d9a50ac` on port 8100, scratch DB
  `vaultaire_s3dlab` (schema-only dump of prod's `vaultaire`, role `s3dlab`),
  `STORAGE_MODE=sia`, no master key. Lab files in `~/s3dlab/` on the box
  (lab.env holds the DB password and S3 keys; server stopped after the bench —
  restart: `set -a; . ~/s3dlab/lab.env; set +a; ~/s3dlab/vaultaire-s3dlab`).
- Data: /dev/urandom (incompressible). Durability measured with `s3d flush`
  (a PUT 200 is buffered on s3d's local disk — 10 GiB default — and uploaded
  to Sia by its background loop; "auto flush" interval landed upstream

## Conformance (Mac, 2026-10-21)

CreateBucket, PUT (ETag = body MD5), HEAD, GET byte-match, Range GET,
ListObjectsV2, 16 MiB multipart byte-match, DELETE→404: **all pass**.
Post-flush reads match (served from the Sia network, local buffer 0 B).
s3d gaps that don't block a target-only leg: tagging, bucket policies,
POST Object, lifecycle filters; object lock landing upstream this week.

## Findings

1. **Vaultaire adds almost nothing to accept latency** — multipart + chunking
   accept 1 GiB at ~295 MB/s; s3d's local buffer absorbs it.
2. **Chunked flushes slower than whole** (~25–30 MB/s vs ~137 MB/s logical):
   a chunked object is ~65 separate ≤16 MiB s3d objects; s3d packs them into
   slab groups (log: "uploading object group … waste 2–28 %") but per-object
   overhead and padding waste dominate against one 1 GiB stream.
3. **Chunked reads have fat tails** (87→7→25→37 MB/s across four identical
   1 GiB GETs): every chunk GET is a fresh Sia host lottery, and one slow host
   stalls the ordered stream; vaultaire's chunk hedge (400 ms) hedges against
   s3d, not against s3d's hosts. Raw whole-object reads were far more
   consistent (85–107 MB/s). **For a `sia` tier, prefer whole objects** —
   `storageClassDisablesChunking` for a SIA class, like RESILIENT/SYNC — or
   accept the tail.
4. **Durability semantics**: like the Sync bridge, a 200 is not on-Sia.
   A `sia` leg needs either flush-aware settlement or acceptance of the lag
   (s3d's auto-flush interval is configurable upstream since 2026-10-20).

## Verdict + open items

Works end-to-end through the real customer path with zero driver-specific
code beyond registration. Rates on the FREE plan already sit between Sync
(~110 MB/s rebuild) and Lyve: good enough for a target-only tier or parity
leg. Open (owner): paid-plan upgrade before sustained benches (we hold 50 GB),
**sia.storage ToS check for reselling under customer data**, whether the tier
ships whole-object-only, and an s3d systemd unit if this graduates from lab.

## Optimized run (2026-10-21, same lab): chunking OFF + parallel_get ON per tenant

Two per-tenant flag rows, zero code: `chunking=false` (simulates the
whole-object-only `sia` tier — multipart Completes store as ONE blob) and
`parallel_get=true` (the fixed-bucket driver implements `GetRangeInfo`, so
`sia` is parallel-read eligible automatically).

| Op | Baseline (chunked) | Optimized (whole) |
|---|---|---|
| PUT 1 GiB accept | 3.47 s | 2.95 s |
| **Durable on Sia, 1 GiB** | 34.4 s (~30 MB/s) | **7.9 s (~135 MB/s)** — 4.5× |
| GET 1 GiB, gateway busy | 87/7/25/37 MB/s | 90/67/40/11 MB/s (still fat-tailed) |
| **GET 1 GiB, gateway quiet** | — | **13.2 s / 13.2 s (~78 MB/s, stable)** |

Head row verified `backend_name = sia` (not `chunked`), byte-compares pass.

### What the read investigation found

1. **The fat read tail is read/write contention at the single s3d gateway,
   not Sia.** Controls: a fresh 512 MiB object read raw 3× right after its
   flush = 4.7–5.8 s consistent (~90–108 MB/s from the network); the same
   1 GiB that read at 7–40 MB/s through Vaultaire during s3d's background
   uploads read at a stable 78 MB/s once the gateway was quiet. Same lesson
   as the single Sync bridge (2026-10-06) — and the same fix shape: **run
   several s3d instances** (one seed registers many; we already run two) and
   route/fan like the multi-bridge driver, or keep reads off the leg during
   heavy ingest.
2. **`parallel_get` barely engages for real clients**: aws-cli splits
   downloads into 8 MiB ranged parts, below the 64 MiB parallel threshold —
   only 2 requests took the parallel path (single ranges ≥ 64 MiB), and its
   slow-range hedge fired 15× during the busy window. It is not the lever
   here; whole-object placement is.
3. **Whole-object placement is the one decision that matters**: 4.5× durable
   write rate, one s3d object per key (no slab-packing waste), consistent
   reads. A `SIA` storage class belongs in `storageClassDisablesChunking`.
4. s3d serves recently-written/read blobs from local disk at memory speed
   (the 1 GiB read raw in 0.4 s) — nice for hot-read patterns, irrelevant
   for the durability story.
5. The bench tenant tripped the egress allowance counter 421× (free-tier
   allowance, `egress_throttle` off → counted, not paced) — a reminder that
   a real `sia` tier bench needs a tenant with a bought house.
